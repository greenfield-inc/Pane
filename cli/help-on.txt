For people:
Open a Session for each workstream and tell its agent what you want, in plain words. It plans the work, starts a Pane for each feature, and runs the builders, reviewers and QA as tabs inside them, so you don't have to. Anything that needs you, like a decision, an approval or a merge, waits for you in Approvals while everything else keeps moving. When a feature is done, archiving its Pane cleans up its worktree and files for you.

For agents:
In Pane, work flows from a Session to Panes to tabs. A Session is a workstream: the person or an orchestrator opens it, and every Pane created or adopted from inside it joins it. When you are in one ($PANE_SESSION_DIR is set: you orchestrate it or your Pane belongs to it), start new Panes from there (each result's `association` names the Session they joined); when you are in none, work with several parts starts a new Session. Each feature gets one Pane, a git worktree on its own branch, and everything for that feature (the agent that builds it, its reviews, QA and fixes) runs as tabs inside it. Scratch files go in $PANE_SCRATCH_DIR inside the Pane. When the feature is done, archive the Pane and Pane cleans up its worktree, tabs and scratch files. When you need the person, ask through Approvals (a Session worker reports blocked to its orchestrator instead).

  npx --yes runpane@latest
  npm i -g runpane && runpane setup

  npx --yes runpane@latest install daemon --label "My Server"
